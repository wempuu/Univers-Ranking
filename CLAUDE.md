# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Univers-Ranking is a pop culture mini games website (French UI), hosted on GitHub Pages from the `main` branch root.

## Stack

Plain static HTML/CSS/JS — no build step, no dependencies, no tests yet. Pages `fetch` `data/mangas.json`, so preview through a local HTTP server (opening files via `file://` breaks the character pages). Pushing to `main` redeploys the site.

## Architecture

- `index.html` + `accueil.js` — home page as two full-screen "pages" (`.fp-panel`, `body.fp`): 1) Accueil (hero + collage + a single "Jouer" button to jouer.html + "Scrolle vers le bas pour découvrir les jeux"; the user wants only that one button there), 2) Undercover (`#undercover`, rules + collage + footer, no button). Wheel, swipe or arrow keys at the bottom/top edge of a page switch pages with a clip-path/slide transition (1.1 s lock against trackpad inertia); each page scrolls inside its own `.fp-scroll`; `#undercover` in the URL opens page 2 directly (jeux.html links there). Add a game page by adding another `.fp-panel` + pagination button. 
- `jouer.html` + `jouer.js` — "Jouer" page (opened by the home "Jouer" button): create a group (pseudo + random 6-char code from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, no 0/O/1/I/L) or join one with a code. The pseudo is kept in localStorage (`ur-pseudo`).
- `groupe.html?code=XXXXXX[&hote=1]` + `groupe.js` — group lobby, serverless: PeerJS 1.5.4 (unpkg, public PeerJS broker, WebRTC). The creator (`hote=1`) claims peer id `univers-ranking-<code>` and is authoritative: holds `state = { players, game, rules, status }` and broadcasts it to every guest on each change; guests connect to that id, send `{type:"join", name}` and only render. Only the creator can pick the game and edit rules; max 12 players; if the creator leaves or closes the page the group ends for everyone. Game flow (Undercover) lives in `groupe.js` too: the host draws characters and roles, sends each player only their own character (`{type:"secret"}`), runs turns/timers (`deadline` in host time + `hostNow`, guests correct for clock offset) and keeps roles/votes private until the result.
- `jeux-liste.js` — `GAMES` catalogue of group games (`minPlayers`, rules) with each game's editable `rules` (`number` / `select` / `toggle`, with defaults); the lobby builds its game picker and rule fields from it. Add games here.
- `catalogue.html` + `catalogue.js` — catalogue of universes with a search bar (filters manga cards by title only; the `.grid` uses `auto-fill` so a lone result keeps its normal width); "Mangas" section with one `.card.manga` per series (cover image from `images/catalogue/<slug>`, shown at 2:3; the `--c1`/`--c2` gradient is the fallback behind it).
- `data/mangas.json` — single source of truth: `{ tags: { <tag-slug>: { label, values: [tags in order], rarity: { <tag>: 1|2|3 } } }, mangas: { <manga-slug>: { title, cover, groups: [{ id, label }], characters: [{ name, group, image?, imageSource?, imageCrop?, tags: { <tag-slug>: [values] } }] } } }`. Empty `characters` shows "Liste à venir".
- Groups (categories) are per manga and are not tags (they are series-specific). The characters array is kept sorted by group (in `groups` order), and within a group by importance in the story; the list page shows one heading per group, no ranks or vote counts. A character whose `group` is unknown falls into the last group. Empty `groups` = one flat list. One Piece groups: Pirates > Marine & Gouvernement > Révolutionnaires > Autres (103 characters; Kuzan is filed under Marine despite joining Blackbeard; every former Warlord — Mihawk, Crocodile, Kuma, Weevil… — is under Pirates; the Five Elders, Garling and the Holy Knights are under Marine & Gouvernement). The user and their friend manage the order by hand through the editors: never reorder characters or choose a position by importance — append new characters at the end of their group and keep the existing order). Selection history: popular top 20, missing Straw Hats, admirals, 4 revolutionaries (Dragon, Sabo, Ivankov, Karasu), bounties down to ~700 million, then key arc characters, then (2026-11) every former Warlord missing (Kuma, Weevil), the Five Elders (Mars, Warcury, Nusjuro, Ju Peter, plus Garling who replaced Saturn), the four Holy Knights seen in Elbaph (Shamrock, Sommers, Killingham, Gunko) and Tashigi; then the main antagonist of each arc not already there (Morgan, Kuro, Don Krieg, Gem/Mr. 5, Galdino/Mr. 3, Wapol, Bellamy, Foxy), the top 3 members of each Emperor crew not already there (Benn Beckman, Lucky Roux, Yasopp, Shiryu, Jesus Burgess, Jozu), Bepo and Killer; all now have a portrait and tags.
- Tags exist so mini games can group characters across works. Since 2026-11-21 the tag set is the user's official list (a full overhaul that replaced every earlier tag through an old→new migration): 4 categories, in this order — `physique` (Physique, 34 tags: Homme, Femme, Enfant, Âgé, Grand, Petit, Musclé… plus races/body types Humain, Non-humain, Animal anthropomorphe, Démon, Dieu / Divinité, Cyborg, Squelette…), `role` (Rôle, 32: Protagoniste, Antagoniste, Personnage secondaire, Allié, Leader, Bras droit, Soldat, Chef militaire, Roi / Reine, Prince / Princesse, Empereur, Pirate, Criminel, Conseiller…), `style-de-combat` (label "Combat", slug kept; 36: Force brute, Épée, Katana, Arme blanche, Armes à feu, Arme lourde, Transformation, Contrôle du feu…), `caractere` (Caractère, 31: Joyeux, Sérieux, Calme, Sadique, Naïf…). Each category's `values` is exactly that list in the user's order, and `rarity` maps every tag to 1 (⭐ Commun), 2 (⭐⭐ Rare) or 3 (⭐⭐⭐ Très rare); `tagRarity()` / `rarityStars()` / `RARITY_LABELS` in common.js read it (missing = 1). Each tag belongs to exactly one category (no value in two categories); a character can have several tags per category. Use the list's exact (accented) spellings; do not add tags outside it unless the user asks. The `univers` category was deliberately deleted — do not recreate it. Characters' tag values inside a category are stored in the list's order. Every One Piece character has all four categories except Dr. Hiriluk (no Combat). Everything tag-related is managed in `tags.html` + `tags.js` ("Gérer les tags", linked from the Catalogue): create/rename/delete categories (deleting strips the category from every character), create/rename/delete tags (renaming onto an existing value merges them and keeps the target's rarity; a plain rename keeps the rarity; new tags are stored in the category's `values` with rarity 1), set a tag's rarity (select), add/remove characters for a tag (all mangas), and a "Recherche multi-critères" card that combines tags from any categories (AND, via `charactersWithTags()` in common.js). Character pages show each chip with its stars. It uses the shared GitHub panel to publish. A category slug never changes on rename. Values must stay generic and reusable across series, never series-specific names.
- `common.js` — shared helpers: `loadData()` (whole file), `loadMangas()` (just `mangas`), `isValidData()`, `knownTagValues()`, `slugify()` (character URL id, derived from the name, so renaming a character changes its URL), `groupCharacters()` (splits a manga's characters by group), `persoAvatar()` (portrait: `image` or initials on a gradient), `askConfirm()` / `askText()` (in-page dialogs returning promises — never use the browser's `confirm()`/`prompt()`: the Claude app's built-in browser silently answers "no"), `normalizeSearch()` / `searchText()` / `matchesSearch()` / `createSearchBar()` (accent-insensitive search that must match the start of a word, letters and words in order — "on" finds "One Piece" but not "Dragon Ball", "monkey d" finds "Monkey D. Luffy"; each label is matched separately; a ✕ button on the right, or Escape, clears it; "/" focuses the bar), `emptyBlock()`.
- `personnages.html?manga=<slug>` + `personnages.js` — character list for a manga; catalogue cards link here, each name links to the character page. A search bar filters characters by name only (not tags), hiding empty group headings.
- `personnage.html?manga=<slug>&perso=<name-slug>` + `personnage.js` — character page: one block per tag category showing its values as read-only chips, plus previous/next links. Tags are NOT editable here any more (use tags.html). Clicking the portrait pencil mounts the GitHub panel ("✕ Fermer" closes it) and, once connected, opens `image-editor.js` (`openImageEditor`): it opens the FULL image (`imageSource`) framed as the current portrait (`imageCrop`), lets you zoom (slider, −/+ buttons, mouse wheel, up to ×12) and drag with click-and-hold, or pick another file. Valider closes the window at once and then, in the background (progress and errors shown in the panel status), exports a 320×320 JPEG portrait uploaded with `panel.putFile()` over the existing portrait path (default `images/personnages/<manga>/<perso-slug>.jpg`), uploads the full image too only when it changed (to `images/personnages/<manga>/originaux/<slug>.jpg`, max 1400 px JPEG), and stores the crop; paths get `?v=<timestamp>` for cache busting. The data change still needs "Publier". Without `imageSource` the editor falls back to the current portrait as source. "Retirer l'image" drops `image`, `imageSource` and `imageCrop` (files stay in the repo).
- `outil.html` + `outil.js` — "Modifier la liste" editor: names, groups and order only (add with a group, rename, change group via a select (moves to the end of that group), reorder within a group by arrows or across groups by drag (adopts the target's group), delete, duplicate check)., with each row's portrait. No tag editing here. Reachable from "Modifier la liste" on each character list; not linked in the nav. "Fermer l'édition" goes back to that manga's character list (asks first if there are unpublished changes).
- `github-panel.js` — `createGitHubPanel({ mount, getData, onData })`, shared by both editors: token login, branch picker / creation, reload, publish, plus `putFile(path, base64, message)` to commit another file (used for portraits). Publishing: "Publier sur GitHub" commits `data/mangas.json` to the branch picked in the editor (default `main`, the only branch the site shows; a "Nouvelle branche" button creates one from the current branch) through the GitHub contents API (`PUT /repos/wempuu/Univers-Ranking/contents/data/mangas.json` with the last known `sha`, so a concurrent edit is refused instead of overwritten; if the branch has no data file yet, publishing creates it). Each user pastes their own GitHub token (owner: fine-grained, Contents read+write on this repo; collaborators: classic `public_repo`), stored only in that browser's localStorage (`ur-github-token`); when connected the panel loads the file from the API, not from Pages. Both editors publish the whole file, so the sha check is what protects concurrent edits made in the other editor.
- Testing editors in the local preview browser: the user may have a real token saved in that browser's localStorage. Never submit a fake token or call `storeToken` there without checking `localStorage.getItem("ur-github-token")` first, and mock `fetch` before any action that could publish.
- Because the editor commits straight to GitHub, the local clone falls behind: always `git pull` before editing anything locally, especially `data/mangas.json`.
- Character portraits: optional `image` field, e.g. `images/personnages/one-piece/<slug>.jpg` — 320×320 JPG cropped on the head. `imageSource` is the full image it was cut from (`images/personnages/one-piece/originaux/<slug>.jpg`, about 18 MB for the 98 One Piece originals) and `imageCrop` is `{ x, y, w }`: top-left corner as fractions of the full image width/height, and the square side as a fraction of its width. Shown round, both in the list and big in the character page (the image editor dims what falls outside that circle); no image = initials. User rule for One Piece: color art drawn by Oda from the manga only (digitally colored manga, manga color schemes, covers); never anime screenshots or anime/film promotion. Provenance of each file is in `images/personnages/one-piece/SOURCES.txt` (One Piece Wiki file names). Every character has one. User-approved exceptions: Uta uses the Film Red promo art drawn by Oda, Imu a black-and-white manga panel; Xebec and Shiki come from the volume 114 cover. Garling uses a black-and-white manga panel (user-approved exception, like Imu): the wiki has no colored manga art of him. Crop positions were tuned by eye so the face sits in the middle of the square.
- `jeux.html` — games menu: one card per game (they are played from a group, so cards link to the home page group section).
- `undercover.js` — Undercover rules: innocents share one character, impostors get another one sharing at least 3 tag values with it, each in a different tag category (`pickCharacters`, compares normalized values); impostors auto = 1 up to 4 players, 2 for 5–7, 3 for 8–10, 4 for 11–12 (or the host's choice, always fewer than half); word rounds = 2 + (impostors − 1). Players don't know their role. Each turn one word (no spaces, 30 chars; timeout = skipped turn); then everyone votes once; a single most-voted player is eliminated (tie = nobody); innocents win only if an impostor is eliminated. Reveal shows both characters, one shared tag per category, roles and vote counts. Fewer than 3 remaining players aborts the game; late joiners spectate.
- `style.css` — shared styles (color tokens on `:root`) for every page, editorial dark look inspired by the "Tetsuo" theme: near-black `#121212`, orange `--accent #f26b1d`, Barlow Condensed uppercase headings + Barlow body (Google Fonts), sharp 2px corners, outlined uppercase `.btn` (`.btn.solid` = orange), faint vertical grid lines, image collages (`.collage` with `.duo` orange duotone / `.bw` / `.framed`), shared `.site-footer` on every page; includes `.grid` / `.card` for game listings.
- All pages share the same header/nav (Accueil, Catalogue, Jeux); keep them in sync when editing.
- `.nojekyll` — tells GitHub Pages to serve files as-is.
- Cache busting: every page loads `style.css?v=N` and `*.js?v=N`. GitHub Pages caches files for 10 minutes, so a browser can mix new HTML with old JS after a deploy. When changing any CSS/JS, bump `N` in all `*.html` files (currently `v=26`; e.g. `sed -i "s/?v=26\"/?v=27\"/g" *.html`).

To add a game: create `jeux/<game>.html` (+ `.js`), link `../style.css`, and in `jeux.html` replace the `.empty` block with a `.grid` of `<a class="card">` entries.

## Workflow

- Always ask the user before every `git push`, for each change, even small ones and even if earlier pushes were approved. Commit locally, then ask; push only after a fresh yes.
